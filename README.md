# Programmable V4 launch package

> **PRE-LAUNCH DRAFT:** Nothing in this repository is deployed, submitted, signed, broadcast, live, source-verified, externally audited, or approved by Programmable. No official V4 contract address exists in this package.

This repository prepares a fixed-supply `Programmable` (`V4`) token and one canonical native-ETH/V4 Uniswap v4 pool on Robinhood Chain Mainnet (`chainId 4663`). It deliberately keeps launch-time prices, amounts, addresses, hashes, metadata URI, API authorization, and signatures out of the static source package.

## Bound design

- Supply is exactly 1,000,000,000 V4 with 18 decimals. There is no later mint.
- The constructor sends 950,000,000 V4 to `0x245099E77F8F0Cad9a75B1B56db8FDE7C948d5B1` and 50,000,000 V4 to the one-shot initializer.
- The initializer creates the canonical native-ETH/V4 dynamic-fee pool, mints one full-range LP NFT to the launch wallet, and performs the launch wallet's initial buy atomically.
- The canonical pool charges a 30% LP fee for the first 30 seconds, beginning with the atomic initial buy, then switches permanently to 1%.
- This is an LP fee, not a token transfer tax. It applies only to swaps in the canonical hooked pool. Other pools or direct token transfers are not forced to charge it.
- Fees accrue to active LPs according to their liquidity share, subject to Uniswap protocol accounting. The launch wallet receives fees only to the extent its position provides active liquidity; fees are not automatically reinvested.
- The initial LP NFT is unlocked at launch and belongs to the launch wallet. A later lock or burn is a separate, irreversible operation and is not implemented here.
- Anyone may later create additional compatible LP positions. Each LP controls only its own position.
- Migration and treasury transfers are separate post-launch operations. They are not executed by the initializer.

The planning reference is $0.002 per V4, corresponding to a $2,000,000 fully diluted valuation for one billion tokens. The liquidity intent is up to 50,000,000 V4 paired with approximately $100,000 of ETH, plus an approximately $100 gross initial buy. These USD figures are not enforced by an oracle. Exact ETH, Q64.96 price, liquidity principals, slippage bounds, and deadline must be derived from a fresh launch-time quote.

## Repository map

- `src/ProgrammableToken.sol` — immutable fixed-supply ERC-20.
- `src/ProgrammableLaunchFeeHook.sol` — canonical-pool initialization guard and dynamic LP-fee schedule.
- `src/ProgrammableLaunchInitializer.sol` — one-shot atomic initializer, LP mint, and initial buy.
- `test/` — contract and integration tests.
- `metadata/` — approved local logo bytes and draft token metadata.
- `config/launch-intent.json` — non-official static intent; unresolved launch-time values stay `null`.
- `config/trust-roots.snapshot.json` — recorded addresses and explicit revalidation gates.
- `config/supply-plan.json` — exact one-billion-token reconciliation.
- `config/programmable-v4-pack-readiness.md` — exact missing fields and the public V4 release gate.
- `scripts/build-pack-artifacts.mjs` — credential-free deterministic Standard JSON and compiler-artifact builder.
- `build/programmable-v4/` — generated noncanonical pack inputs and their hash manifest.
- `distribution/` — canonical post-launch migration allocation package and verifier.

No hand-authored `launch.json` is included. Any official platform payload, deployment graph, predicted addresses, code hashes, or signature digest must be generated by the official Programmable tooling from the final immutable source. Source CLI 4.0.0 may be used only through a separately authorized, chain-scoped internal-key lane while the public self-service release remains closed.

## Local verification

Requires Node.js 24+, npm, Foundry, and the pinned dependencies in `package-lock.json`.

```sh
npm ci --ignore-scripts
npm run build:pack-artifacts
npm run fmt:check
npm run build:production
npm test
npm run test:fuzz
npm run verify:distribution
(cd distribution && shasum -a 256 -c SHA256SUMS.txt)
```

A local pass is development evidence only. It is not an external audit, platform approval, deployment receipt, onchain verification, routing admission, or trading-terminal availability proof.

## Launch-time gates

Before the launch wallet signs or funds anything, all of the following still need fresh evidence:

1. Programmable's V4 backend currently reports `ready`, while public discovery still reports `status: planned`, `activationStage: planned-not-deployed`, `publicAuthorization: false`, `publicWrites: false`, and `releaseReady: false`. Those flags keep public self-service closed. They do not replace the separate authenticated preflight for an internally approved, chain-4663-scoped key; that preflight must independently prove create scope, chain grant, controller binding, and simulation before submission.
2. The final source revision and lockfile must be immutable and used by the official platform packer; its generated addresses, bytecode hashes, request digest, and calldata must be checked rather than recreated by hand.
3. Robinhood Chain and every used Uniswap/Programmable runtime must be rebound to a fresh finalized block and verified by address, bytecode hash, and required contract linkage. The current official Uniswap Universal Router is `0x06AfBA43Fd06227fA663b0DAecF536f6EaA6bf99`; the old `0x8876789976dEcBfCbBbe364623C63652db8C0904` instance is explicitly historical/orphaned and must not be used for a new launch.
4. The logo must be pinned permanently and the placeholder in `metadata/token-metadata.json` replaced.
5. A fresh ETH/USD input must produce the exact `initialSqrtPriceX96`, native LP budget, previewed LP principals, initial-buy input, minimum output, price limit, and deadline.
6. The final build, complete tests, fork-context simulation, security review, and bytecode-size checks must pass for the exact submitted bytes.
7. The launch wallet owner must independently review the final summary, approve the funding amount, and sign. No key or secret belongs in this repository.
8. After confirmation, source verification, canonical pool state, LP NFT custody, fee schedule, route/quote behavior, and public discovery must be checked independently. A deployment transaction alone does not prove trading-terminal support.

The exact migration package should be executed only after those launch and LP checks. See `distribution/README.md` and `SECURITY.md`.
